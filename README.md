# Noise Detection Dashboard

A small project to visualize binary (0/1) noise-sensor data on a floor plan.

This repo contains:

- `api/` — Express API that queries InfluxDB and exposes `/getdata`.
- `dashboard/` — React + Vite frontend that renders an interpolated noise heatmap and device overlays.

Key concepts

- Sensors report binary samples (0/1). A value of `1` means the sensor exceeded its local threshold at that sample time.
- The frontend computes per-device duty cycle p = (# of 1s) / N over the selected time window and visualizes p as a heatmap.
- The heatmap is generated by inverse-distance weighting (IDW) from device positions into a canvas overlay for performance.

What changed / new features

- Period selector: pick a recent window (5m, 10m, 30m, 1h, 6h, 24h). Default: last 10 minutes.
- Custom range: switch to "Custom" and set `start` / `stop` with local `datetime-local` inputs, then click Apply.
  - The UI shows the currently-applied range above the maps (local time) and exposes UTC ISO in a tooltip for debugging.
  - `stop` enforces a minimum equal to `start` and the start field will auto-advance `stop` if needed.
- Offline marker legend: an explicit legend explains the red dashed ring + dot + cross means "offline / no samples".
- Device labels: optional small name badges; offline devices display a dimmed badge and "(offline)" tag when enabled.

How the frontend computes values

- For each device the frontend calls `fetchData(start, stop, device)` and receives rows from the backend.
- The frontend filters values to 0 or 1 and computes:
  - `count = nums.length` — the number of samples returned for that device and window
  - `p = count ? sum(nums) / count : 0` — duty cycle used for interpolation and marker sizing
- A device with `count === 0` is treated as offline for the selected window and is rendered with the offline symbol.

Important notes about timezones and queries

- The `QueryBuilder` and the `NoiseMap` custom range inputs use `datetime-local` (local timezone) and convert to ISO UTC when submitting to the backend; components should pass ISO `start`/`stop` strings to the API without applying manual timezone offsets.
  - Example: `new Date(localInput).toISOString()`.
- If you see an unexpected -7h or other shift, it usually means a manual offset was applied in the frontend in addition to the browser's timezone conversion. The app now sends the ISO strings directly to the backend.

Backend behavior and performance

- Currently the API returns raw InfluxDB rows (no aggregation). That means `count` equals the number of rows returned for each device/time window.
- Requesting very large windows (days/months) will retrieve many rows and increase query time and network load.

Recommended server-side options (optional improvements)

- Server-side aggregation: return per-device summaries (e.g., `count`, `mean`) instead of raw rows to reduce payload and CPU overhead in the browser.
- Single-query summaries: query all devices in one aggregated Flux query to avoid N round-trips.
- Downsampling / aggregateWindow: use `aggregateWindow` or `count()`+`mean()` in Flux so the API returns a compact summary suitable for large windows.

Developer notes & files of interest

- `dashboard/src/components/NoiseMap.tsx` — main visual: IDW heatmap (canvas) + SVG overlays, period/custom range UI, legend and controls.
- `dashboard/src/components/DemoNoiseMap.tsx` — demo-only map using `dashboard/src/sample/sampleData.ts`.
- `dashboard/src/components/ImageDemoMaps.tsx` — image overlays for library floors with device positions.
- `dashboard/src/config/devices.ts` & `dashboard/src/config/imageDevices.ts` — device coordinates and image mappings.
- `api/server.js` — POST `/getdata` implementation and Flux query used to fetch rows from InfluxDB.

Run locally

1. Start the API (set `INFLUX_*` env vars in `api/.env`):

```bash
cd api
npm install
npm run dev
```

2. Start the frontend:

```bash
cd dashboard
npm install
npm run dev
```

3. Open the URL shown by Vite (default `http://localhost:5173`). Use the navbar to open the demo or the main map.
